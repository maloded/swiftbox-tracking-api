# CLAUDE.md — SwiftBox Tracking API

## Что строим
Небольшой бэкенд на NestJS + Prisma + PostgreSQL для тестового голосового
ИИ-агента (Hanc.ai). Полная спецификация — в `TZ.md` в этой же папке. Прочитай
его первым делом, прежде чем писать код.

## Приоритеты
1. Рабочий `docker-compose up` — это главный критерий успеха. Всё остальное
   вторично по сравнению с "поднимается одной командой и отвечает на запросы".
2. Простота важнее полноты. Это тестовый/демо-проект, не продакшен-система.
   Не добавляй авторизацию, rate limiting, сложную обработку ошибок сверх
   того, что описано в ТЗ.
3. Сиды обязательны и должны реально сработать при первом старте — без них
   API бесполезен для теста.

## Стек и структура
- NestJS, стандартная модульная структура (`tracking` module с controller +
  service, `complaint` можно как часть того же модуля или отдельным).
- Prisma как ORM, схема — как в ТЗ.
- Пиши на TypeScript, следуй обычным NestJS-конвенциям (DTO классы,
  `class-validator` декораторы, `@Injectable()` сервисы).

## Порядок работы
1. Прочитай `TZ.md`.
2. Инициализируй NestJS-проект (`nest new`, если ещё не создан).
3. Настрой Prisma: `schema.prisma` по модели из ТЗ, миграция.
4. Напиши seed-скрипт (`prisma/seed.ts`), сделай его идемпотентным (upsert).
5. Реализуй эндпоинты по одному, в порядке из ТЗ: health → GET tracking →
   PATCH reschedule → POST complaint.
6. Напиши `Dockerfile` (multi-stage) и `docker-compose.yml` (api + db с
   healthcheck).
7. Настрой так, чтобы при старте контейнера сами применялись миграции и сиды
   перед запуском сервера (entrypoint-скрипт или CMD-цепочка в Dockerfile).
8. Проверь вручную через `curl` все 5 сценариев из раздела "Критерий
   готовности" в ТЗ. Не считай задачу законченной, пока все 5 не прошли.

## Что НЕ делать
- Не переусложняй структуру папок сверх того, что нужно для 3 моделей и
  3-4 эндпоинтов.
- Не пиши тесты, если явно не попросят — для этого демо-проекта они не
  критичны, время лучше потратить на то, чтобы сам API рабочий и стабильный.
- Не меняй названия полей/эндпоинтов из ТЗ без явного запроса — их будет
  использовать внешняя система (Hanc.ai Tool-нода), которая ожидает точную
  структуру ответа как описано.

## Финальный отчёт
После завершения — выведи в чат:
- Финальную структуру проекта (`tree` или аналог)
- Точные `curl`-команды для всех эндпоинтов с примерами ответов
- Порт и .env, которые нужны для запуска
- Всё, что отклонилось от ТЗ и почему (если пришлось)
